# 🤝 Contributing to LifeOps

Thank you for your interest in contributing to **LifeOps**! 🎉

Whether you're fixing a bug, improving documentation, enhancing the UI, or adding a new feature, every contribution is appreciated.

---

# 📌 Before You Start

* Search existing Issues before creating a new one.
* If your change is significant, create an Issue first to discuss the idea.
* Keep Pull Requests focused on a single feature or fix.

---

# 🚀 Getting Started

## 1. Fork the repository

Click **Fork** at the top-right of the repository.

---

## 2. Clone your fork

```bash
git clone https://github.com/YOUR_USERNAME/LifeOps.git

cd LifeOps
```

---

## 3. Install dependencies

```bash
npm install
```

---

## 4. Create a new branch

```bash
git checkout -b feature/your-feature-name
```

Examples:

```text
feature/add-dark-mode

feature/improve-dashboard

fix/navbar-overflow

docs/update-readme
```

---

## 5. Make your changes

Write clean, readable, and maintainable code.

Please follow the existing project structure and coding style.

---

## 6. Test your changes

Run the development server:

```bash
npm run dev
```

Ensure your changes work correctly and do not introduce new issues.

---

## 7. Commit your changes

Use clear and meaningful commit messages.

Examples:

```text
feat: add CSV validation

fix: resolve mobile navbar issue

docs: update installation guide

refactor: simplify dashboard layout
```

---

## 8. Push your branch

```bash
git push origin feature/your-feature-name
```

---

## 9. Open a Pull Request

When submitting your PR, include:

* A clear title
* A concise description
* Screenshots (if UI changes)
* Reference related issues (e.g., `Closes #12`)

---

# 💡 Ways to Contribute

You can help by:

* Fixing bugs
* Improving UI/UX
* Enhancing accessibility
* Improving documentation
* Adding tests
* Optimizing performance
* Refactoring code
* Suggesting new features
* Improving responsiveness
* Fixing typos

---

# 📝 Coding Guidelines

* Use TypeScript.
* Keep components modular and reusable.
* Write descriptive variable and function names.
* Avoid unnecessary dependencies.
* Follow the existing folder structure.
* Keep pull requests focused and easy to review.

---

# 🐛 Reporting Bugs

When reporting a bug, please include:

* Expected behavior
* Actual behavior
* Steps to reproduce
* Screenshots (if applicable)
* Browser/OS information

---

# ✨ Feature Requests

Feature requests are welcome.

Please describe:

* The problem you're trying to solve
* Your proposed solution
* Any alternatives you've considered

---

# 📋 Pull Request Checklist

Before submitting, make sure you have:

* Read this guide
* Tested your changes
* Updated documentation if needed
* Used meaningful commit messages
* Resolved merge conflicts
* Ensured the project builds successfully

---

# 🌟 Community

Please be respectful and constructive when interacting with others.

We strive to maintain a welcoming and inclusive environment for everyone.

Happy contributing! 🚀
